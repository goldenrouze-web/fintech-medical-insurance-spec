# Форма создания заявки на выпуск полиса ДМС
## Назначение 
Спроектирован пользовательский интерфейс создания заявки на выпуск полиса ДМС на основании API-контракта POST /applications. Форма учитывает обязательные поля, правила валидации, отображение ошибок и обработку ответов сервера.

[ссылка - API управления полисами добровольного медицинского страхования](https://github.com/goldenrouze-web/fintech-medical-insurance-spec/blob/main/openAPI)

![Макет формы создания заявки на полис](./Диаграмма%20без%20названия.drawio-4%2013.46.25.png)

---
## Предусловия
Перед открытием формы должны выполняться следующие условия:
- пользователь успешно авторизован;
- получен JWT Token;
- известен идентификатор страхователя;
- выбрана программа страхования;
- определён тип программы;
- пользователь обладает правами на создание заявки.

## Сценарии валидации и отображение в UI

| Сценарий | Условие | Область проверки | Отображение в UI |
|-----------|----------|------------------|------------------|
| **Успешное создание заявки** | API возвращает `201 Created` | Серверная обработка запроса | Отображается экран **«Полис успешно создан»** с данными созданного полиса. Пользователь перенаправляется на экран успешного создания. |
| **Некорректные данные** | Не пройдена клиентская валидация или API возвращает `400 Bad Request` | Клиентская и серверная валидация | Поля с ошибками подсвечиваются красной рамкой. Под формой отображается сообщение **«Ошибка. Пожалуйста, проверьте данные.»** Введённые значения сохраняются. |
| **Недостаточно прав** | API возвращает `403 Forbidden` | Проверка прав пользователя | Пользователь остаётся на форме. Отображается сообщение **«Ошибка. Недостаточно прав для выполнения операции.»** |
| **Страхователь или программа страхования не найдены** | API возвращает `404 Not Found` | Проверка существования `policyholder_id` или `coverage_program_id` | Пользователь остаётся на форме. Отображается сообщение **«Ошибка. Страхователь или программа страхования не найдены.»** |
| **Повторная отправка заявки** | API возвращает `409 Conflict` (дубликат запроса или ранее созданная заявка) | Проверка идемпотентности запроса (`Idempotency-Key`) | Пользователь остаётся на форме. Отображается сообщение **«Ошибка. Ранее заявка уже была отправлена.»** |
| **Превышен лимит запросов** | API возвращает `429 Too Many Requests` | Ограничение количества запросов | Пользователь остаётся на форме. Отображается сообщение **«Превышен лимит запросов. Повторите попытку позже.»** |
| **Ошибка авторизации** | API возвращает `401 Unauthorized` | Проверка JWT-токена | Пользователь перенаправляется на страницу авторизации или отображается сообщение **«Необходимо повторно выполнить вход в систему.»** |
| **Ошибка сети или недоступность сервиса** | Отсутствует ответ от API (таймаут, недоступность сервиса) | Доступность сервиса | Пользователь остаётся на форме. Отображается сообщение **«Сервис временно недоступен. Попробуйте позже.»** Все введённые данные сохраняются. |

# Постусловия

## Успешный сценарий

* Заявка на выпуск полиса ДМС успешно создана и зарегистрирована в системе.
* Пользователю отображается сообщение **«Полис успешно создан»**.
* Созданному полису присвоен уникальный идентификатор (`policy_id`).

---

## Неуспешный сценарий

* Если заявка не создана, пользователю отображается сообщение об ошибке.
* Если введены некорректные данные, ошибочные поля подсвечиваются, а введённые значения сохраняются.
* Если заявка уже была отправлена ранее, пользователю отображается сообщение **«Ранее заявка уже была отправлена»** и при наличии соответствующей функциональности предлагается перейти к просмотру существующего полиса.
* Если пользователь не имеет прав на создание заявки, отображается сообщение о недостаточности прав.
* Если страхователь или программа страхования не найдены, отображается соответствующее сообщение об ошибке.
* Если превышен лимит запросов, пользователю предлагается повторить попытку позже.
* Пользователь может повторно отправить заявку после устранения причины ошибки, если повторная отправка допускается системой.
* Во всех неуспешных сценариях пользователь остаётся на форме создания заявки, а введённые данные сохраняются для последующего редактирования и повторной отправки.
