# Форма создания заявки на выпуск полиса ДМС

## Назначение

Спроектирован пользовательский интерфейс создания заявки на выпуск полиса добровольного медицинского страхования (ДМС) на основании API-контракта создания заявки.

Интерфейс предназначен для ввода персональных данных застрахованного лица, проверки корректности введённых данных, отправки запроса на создание полиса и отображения результата выполнения операции.

Форма предусматривает:

* клиентскую валидацию пользовательского ввода;
* обработку успешного создания полиса;
* отображение ошибок, возвращаемых сервером;
* сохранение введённых пользователем данных при возникновении ошибок.

**Используемый метод API**

`POST /applications`

**API-контракт**

[ссылка - API управления полисами добровольного медицинского страхования](https://github.com/goldenrouze-web/fintech-medical-insurance-spec/blob/main/openAPI)

# Предусловия

Перед открытием формы должны быть выполнены следующие условия:

* пользователь успешно авторизован в системе;
* получен JWT-токен;
* пользователь имеет доступ к сервису оформления полисов ДМС;
* сервис создания заявок доступен.

> **Примечание**
>
> Идентификатор страхователя (`policyholder_id`) и идентификатор программы страхования (`coverage_program_id`) определяются системой при обработке запроса и не вводятся пользователем.

| ------------------------------------ | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Создание заявки**                  | Пользователь открывает форму                                                | Отображается форма создания заявки с полями **ФИО**, **Дата рождения**, **Серия и номер паспорта**, **Телефон**, **Гражданство** и кнопкой **«Подать заявку»**.                                     |

# Особенности отображения

* Подсветка полей используется только для ошибок валидации пользовательского ввода.
* Ошибки бизнес-логики отображаются отдельным информационным сообщением без изменения состояния полей формы.
* При возникновении серверной ошибки введённые пользователем данные сохраняются.
* Пользователь может повторить отправку заявки после устранения причины ошибки.
* После успешного создания полиса отображается отдельный экран подтверждения без повторного отображения введённых данных.

# Постусловия

## Успешный сценарий

* Заявка на выпуск полиса ДМС успешно создана.
* Пользователю отображается экран **«Полис успешно создан»**.
* Пользователь получает подтверждение успешного завершения операции.
* Пользователь может продолжить работу в системе.

---

## Неуспешный сценарий

* Если введены некорректные данные, подсвечиваются только поля, не прошедшие валидацию.
* Если превышен лимит запросов, отображается сообщение **«Превышен лимит запросов. Пожалуйста, повторите позже.»**.
* Если заявка уже существует, пользователю отображается сообщение **«Ранее заявка уже была отправлена.»** и предоставляется возможность перейти к существующей заявке.
* Если не удалось создать заявку из-за отсутствия программы страхования, отображается сообщение **«Не удалось создать заявку. Программа страхования временно недоступна. Пожалуйста, обратитесь к администратору.»**.
* Во всех неуспешных сценариях пользователь остаётся на форме создания заявки.
* Введённые пользователем данные сохраняются и доступны для повторной отправки после устранения причины ошибки.
